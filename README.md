# رتل — RATTIL

تطبيق إسلامي مفتوح المصدر لحفظ القرآن الكريم وتسميعه واختباره، يعمل على **Android** و**iPhone** بالعربية والإنجليزية والإندونيسية. المصحف والاختبارات وقاعدة بيانات المستخدم تعمل دون اتصال، ولا تُرسل التسجيلات إلى أي خادم.

> **الحالة:** مشروع قابل للتشغيل والتطوير والنشر (Expo SDK 58 + React Native + TypeScript). مبني على واجهات فعلية وقاعدة بيانات محلية؛ لا توجد أزرار تُظهر وظائف غير منفّذة.

---

## 1) التشغيل السريع

```bash
npm install
npm run typecheck     # فحص الأنواع
npm test              # اختبارات المحاذاة والاختبارات والإحصاءات
npm run web           # معاينة في المتصفح (واجهة كاملة؛ الميكروفون يعتمد على المتصفح)
```

بناء التطبيق على الجهاز (يتطلب **development build**؛ لا يعمل في Expo Go لأنه يستخدم وحدة ميكروفون/تعرف أصليّة):

```bash
npm run android       # expo run:android — يتطلب Android SDK
npm run ios           # expo run:ios — يتطلب macOS + Xcode
```

النشر عبر EAS:

```bash
npm install -g eas-cli
eas login
eas build --platform android --profile production
eas build --platform ios --profile production
```

| التسميع الذكي | `app/recite.tsx` + `src/recitation/align.ts`: التعرف الصوتي عبر محرك النظام، كلمة بكلمة، إظهار الكلمات المقروءة فقط، كشف الكلمات الناقصة والمستبدلة والزائدة وتخطي الآيات، إعادة الآية، تلميح عند الطلب، تقرير دقة. |

| الاختبارات | ٩ أنماط حقيقية في `src/quiz/generator.ts`، أسئلتها من السور التي يختارها المستخدم فقط، منها اختبار شفهي يستخدم نفس محرك التسميع. |
| أخطائي | قاعدة بيانات `mistakes` تحفظ السورة والآية والكلمة الصحيحة والكلمة المقروءة ونوع الخطأ والثقة؛ لا يُزال الخطأ من المراجعة إلا بعد إجابتين صحيحتين متتاليتين (`reviewMistake`)، مع إمكانية تحويله لسؤال وإعادة التسميع والاستماع للمقطع عند تفعيل حفظ التسجيل. |
| خريطة المحفوظ | شبكة تفاعلية للسور (١١٤) والأجزاء (٣٠) والصفحات (٦٠٤) بالأخضر/الأصفر/الرمادي وفق حالة الحفظ. |
| المراجعة اليومية | هدف يومي، جدول، تذكير محلي بـ `expo-notifications`، قائمة مراجعات مستحقة، سلسلة الأيام، رسوم أسبوعية وشهرية. |
| الإحصائيات | جلسات التسميع، متوسط الدقة، نقاط الاختبارات، نسبة الحفظ، توزيع على السور والأجزاء. |
| العمل دون اتصال | كل البيانات والنصوص والاختبارات محلية (SQLite + JSON مضمّن). لا يوجد أي طلب شبكة في التطبيق ما لم يفعّل المستخدم صراحةً خيار «السماح بالتعرف عبر الشبكة». |
| الخصوصية | لا خوادم، لا حسابات، لا تحليلات. خيارات: حذف التسجيلات، حذف كل البيانات، نسخة احتياطية واستعادة ملف محلي. |
| الإعدادات | اللغة، الوضع الليلي، حجم الخط، الميكروفون، التذكيرات، الخصوصية، النسخ الاحتياطي، حذف البيانات. |

## 3) محرك التعرف على الكلام — ماذا يعمل وماذا يحتاج جهازك؟

نستخدم مكتبة `expo-speech-recognition` التي تستدعي:

- على Android: `android.speech.SpeechRecognizer` مع `EXTRA_PREFER_OFFLINE`.
- على iPhone: `SFSpeechRecognizer` مع `requiresOnDeviceRecognition`.

**الافتراضي في رتل:** «التعرف على الجهاز فقط» مفعّل، و«السماح بالتعرف عبر الشبكة» معطّل. التطبيق يفحص عند بدء التسميع ما إذا كان الجهاز يدعم التعرف المحلي (`supportsOnDeviceRecognition`) وما إذا كانت نماذج العربية مثبّتة (`getSupportedLocales`)؛ فلا يبدأ التسميع إذا لم يتوفر ذلك، ويعرض رسالة واضحة وزر لتنزيل نموذج العربية على Android.

إذا أردت تعرفاً أعمق بلا اعتماد على نماذج النظام، فالمسار التقني التالي هو دمج محرك Whisper.cpp محلياً عبر وحدة أصلية (GGML/GGUF عربي صغير) — **لم يُضمّن في هذه النسخة** لأنه يتطلب ملف نموذج كبيراً وبناءً أصلياً إضافياً؛ لم ندّعِ وجوده. الواجهة `src/asr/useSpeech.ts` معزولة بحيث يمكن استبدال المحرك لاحقاً دون تغيير منطق التسميع.

## 4) دقة النص القرآني

- النص المعروض يُنسخ حرفياً من مصدر api.quran.com عبر المستودع الموثّق `AlaaJabre/quran-hafs-uthmani` (حفص عن عاصم، مصحف المدينة، ٦٢٣٦ آية، مع أرقام الصفحات والأجزاء)، ولا يُعدَّل في وقت التشغيل.
- أسماء السور وأنواعها من `risan/quran-json` (Tanzil)، والترجمات من Saheeh International وTafsir Sabiq (QuranEnc) للعرض فقط.
- حقل المطابقة (`simple`) مُشتق ميكانيكياً من النص المعروض نفسه بإزالة التشكيل وتوحيد صور الألف والهمزة، حتى تطابق مواضع الكلمات في المطابقة مواضعها في المصحف.
- أعد البناء بـ `python3 scripts/build_quran_data.py`؛ المصادر تُخزَّن مؤقتاً في `.cache/` ولا تُضمّن في Git.
- التفاصيل والاعتراف بالمصادر: `docs/DATA_AND_ACCURACY.md`.


## 6) القيود المعروفة بصراحة

1. التعرف الصوتي يعتمد على نماذج اللغة المثبّتة في نظام الجهاز؛ على بعض الأجهزة يجب تنزيل «Arabic» من إعدادات التعرف على الكلام أولاً.
2. محاذاة الكلمات تستخدم تشابهاً نصياً بعد إزالة التشكيل؛ دقة الكلمات القصيرة والمتشابهة تعتمد على جودة المحرك. النتائج ذات الثقة المنخفضة تُوسم «يحتاج مراجعة».
3. تحليل التجويد استرشادي فقط: التعرف الصوتي العام لا يميّز الحركات والغنة والمدود، لذلك لا يُصدر التطبيق حكماً مؤكداً في التجويد.
4. لا يوجد تأكيد تجويدي من شيخ أو نموذج صوتي متخصص؛ المرجع الشرعي هو التلاوة الصحيحة والمعلّم.
5. النسخ الاحتياطي ملف محلي (JSON) يُشارَك عبر نظام الجهاز؛ لا توجد مزامنة سحابية حفاظاً على الخصوصية.
6. لم تُجرَّب دقة الميكروفون على أجهزة فيزيائية مختلفة ضمن هذه البيئة؛ اختبارات المنطق فقط مُضمنة، ويجب إجراء اختبار ميداني قبل اعتماد النتائج رسمياً (انظر `docs/DATA_AND_ACCURACY.md`).
